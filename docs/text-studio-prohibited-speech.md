# Text Studio 禁止播报检测与人工处理

规则命中默认整句屏蔽，同时允许用户按商品实际权益对具体句子点击 **确认可播报**。确认后句子进入试听和直播，规则命中记录仍然显示；可随时点击 **恢复屏蔽**。原有普通风险的“忽略”不会解除禁止播报。

规则识别范围保留：试吃/试用、免费体验、不要钱、无条件、七天/7天无理由，以及明确的退换、退款、赔付和运费险权益承诺。规则只是提示，不据此断言商品不存在这些权益。商品配置中选择“有运费险”等不会自动全局放行，具体句子由用户确认。

## 页面操作

- 每段命中的句子下方显示原句和规则原因，并提供“定位修改”“确认可播报”。风险抽屉也提供相同操作。
- 确认后显示“规则命中 · 人工已确认可播报”，可在风险抽屉的“人工已确认”筛选中查看，并可“恢复屏蔽”。其他未确认句继续屏蔽。
- 例如 `我给咱们姐妹把宠粉福利做到了，支持七天无理由，还给大家赠送运费险啊。` 可以原文确认，确认后同时保留“无理由售后、运费险权益承诺”的提示，无需被迫改写。
- 原稿、候选和人工编辑内容不因屏蔽而删除；最终播报文本是计算结果。只有确认后的句子恢复，既不全段放行，也不自动放行其他候选中的同文句。
- 整组 Variant 模式同时检查隐藏候选。跨编辑单元的一整句话通过一个操作确认，确认记录对应所有参与单元；修改相邻成员会使该句原确认失效，页面同步刷新相关单元。
- 单段仍全部屏蔽时不能试听；普通直播跳过空段，全文为空时不能启动。整组模式保留原来的成员完整性检查，需处理各版本中被完全屏蔽的单元后再启动。

## 保存与失效范围

项目每个 paragraph 增加可选字段 `prohibited_reviews`，旧项目无字段视为未确认。每条记录包含：

```json
{
  "candidate_index": 0,
  "candidate_text": "确认当时的完整候选文本。",
  "start": 0,
  "text": "具体命中的完整句子。",
  "labels": ["无理由售后", "运费险权益承诺"],
  "rules_version": 1,
  "confirmed_at": "ISO-8601 时间"
}
```

- 记录存放在对应 paragraph 内，绑定候选槽位、完整候选文本、句子位置、句子文本、命中原因和规则版本。
- `start` 使用 Unicode code point 计数，前后端对 emoji 等字符保持一致。跨单元句的位置相对每个成员起点，后续成员可能为负数；匹配仍要求完整句子及所有参与成员一致。
- 一句里命中多条规则时，按钮确认的是显示出来的完整句子和全部原因，不是全局关键词白名单。同一候选中重复出现的相同句子按位置独立处理。
- 保存/打开会恢复确认；恢复屏蔽会移除当前有效确认。确认/撤销动作记录到现有 `replacement_history`，记录不作为放行依据。
- 编辑或事实修正后，内容不再匹配的确认立即失效；重新泛化、整组重生成和复制为新整组项目不会继承旧确认。切换候选不删除其他候选的确认，但不能借用它们。
- 重新检测风险不撤销有效确认，也不会把“已确认”的记录清掉。修改规则时应递增 `config/text-studio-prohibited.json` 的 `version`，旧规则版本的确认不再有效。

TXT 导出包含最终可播报文本。普通智播 JSON 的过滤文本会同时导出对应人工确认并调整位置，避免再次过滤时误屏蔽；整组 JSON 和项目保存保留完整候选及确认记录。

## 试听与直播链路

`web/text-studio-prohibited.js` 与 `server/prohibited_speech.py` 继续共用规则配置；新增 `web/text-studio-reviews.js` 管理人工决定、组内完整句匹配及界面/请求数据。

前端向服务端传递完整候选和准确的确认记录，而不是传入一个“忽略所有屏蔽”开关。服务端重新识别规则并按原文、位置、规则等字段逐项核对：

- Mac `/speak` 试听和 Windows `/synthesize` 试听均先通过 `_tts_preview` 审核；没有确认时保持原屏蔽行为。
- 整组单元试听携带该版本完整上下文，先过滤完整句，再提取所试听成员，避免跨单元确认到后端失配。
- 普通 Live 在 `filter_segments` 中逐候选检查，再进入原有候选选择与合成块逻辑。
- 整组 Live 在准备会话和每轮自然分块时均使用所选候选的确认记录。先判断完整句是否得到所有参与成员的确认，再进行原有分块；不改变候选编号。
- API 只接受结构有效的确认记录；旧 `ignored`、普通风险忽略状态、错误候选编号或失效文本不能解除屏蔽。服务端根据显式传入的人工决定处理，不是多人权限审批系统。

通用 Gateway、CosyVoice、Windows 播放器、缓存和背压不变。

## 生效方式与会话边界

后端更新需要重启 Text Studio，并刷新页面加载新脚本；无需重启 TTS 引擎。本次代码验证未重启现有服务。

确认和恢复屏蔽影响后续试听及新启动的直播会话。已经运行的 Live 使用启动时的审核快照，需停止后重新开始才使用新状态；已经生成/下载的音频不会被追溯修改或删除。页面处理完成后会提示这一点。

## 验证

```sh
python3 -m unittest discover -s tests
node tests/test_text_studio_search.js
node tests/test_text_studio_risk.js
```

自动测试覆盖前后端匹配、用户示例、同文重复句、emoji 偏移、候选隔离、失效规则、确认/撤销的保存恢复、Mac/Windows 试听、普通 Live、跨单元整组 Live 和组内试听。未确认时保留原有屏蔽回归。

`tests/prohibited_reviews_browser_checks.js` 用隔离数据目录、真实页面/API 和模拟 Gateway 验证人工按钮、规则提示保留、试听/直播实际请求、保存重开、撤销、编辑失效、跨单元处理和 JSON 导出；不要在真实直播服务上运行此测试。测试产物保留在 `runtime/prohibited-review-check/`，不提交运行数据。

本轮结果：当前磁盘代码完整回归共 220 项，3 项因环境条件跳过，其余通过；隔离浏览器 23 项检查通过，Node 搜索与风险测试通过。试听和直播验证使用模拟 Gateway 检查真实 HTTP 请求文本，没有播放真实音频。现有正式服务未重启；运行中的会话与音频未改动。
