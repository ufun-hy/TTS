# Text Studio 禁止播报话术

禁止播报是强制的整句屏蔽，不是可忽略的普通风险提示。当前版覆盖试吃、免费试吃、先吃、先试、试用、免费试用、不好吃/不满意不要钱、七天/7天无理由、无条件、不要钱、免费体验、先试后买，以及明确的退换、退款、赔付和运费险权益承诺。

## 页面与编辑

- 原稿、候选和人工编辑内容完整保留在项目中；屏蔽是派生结果，不删除原文。
- 原稿命中的句子标红；当前候选命中的整句显示“禁止播报 · 已屏蔽整句”。“最终智播文本”只显示可播报部分。
- 复用“风险检测”抽屉，增加“禁止播报”筛选和“定位修改”。禁止项没有“忽略”操作；旧的忽略记录也不能解除屏蔽。
- 编辑、切换候选、生成或重新打开项目后重新计算，无需先点击检测按钮。编辑框仍显示完整候选，定位会选中被屏蔽的句子，修改继续自动保存。
- 单段全部屏蔽时不能试听；直播跳过空段，全文为空时不允许启动。TXT 导出只含可播报文本；智播 JSON 只输出可播报段，候选为当前过滤后的最终文本，保留 `original_text` 供原稿追溯。项目保存仍保留全部原始候选。

例如：`大家可以先试吃，不好吃不要钱。口感清甜。` 的最终播报内容为 `口感清甜。`，不会产生只删关键词后的残句。

## 规则边界

以句号、问号、叹号、分号和换行为边界；逗号不是边界，小数点也不拆句。相邻结束标点和右引号随被屏蔽句一同移除。没有结束标点的整段按一句处理。全角字符和句内空格会在匹配时归一化，原文及定位内容保持不变。

试吃/试用、免费体验、不要钱、无条件及七天无理由等显式禁用表达按严格词组匹配，即使在免责声明中提及也会屏蔽。明确权益承诺规则避免把紧邻的否定表达（如“不包赔”“不支持退货”）当作承诺。普通“有问题联系客服处理售后”“按平台规则申请赔付”“退款流程请查看订单”不命中。规则是第一版显式语言匹配，不能穷尽所有同义表达。

时间点和其他普通风险仍按原有方式检测；落在已禁止句中的普通风险不重复列出，也不提供动态时间替换来绕过禁止句。

## 实现与服务端保护

- `config/text-studio-prohibited.json` 是前后端共同规则源。
- 浏览器分析由 `web/text-studio-prohibited.js` 完成；页面区分编辑文本与播报文本。
- `server/prohibited_speech.py` 在 Text Studio 试听请求和直播启动请求处再次过滤。直播过滤发生在候选选择、技术切分及合成块合并前，覆盖所有候选；全部为空返回 HTTP 400，且不调用 TTS 或启动直播。
- 过滤不依赖前端检测状态、风险忽略记录或项目保存时间。普通入口和 `text_studio_entry.py` 的合成块入口均通过同一 HTTP 边界。
- 不改变通用 TTS Gateway 的其他用途，不更改音色、缓存策略或音频编码。

更新后需要重启 Text Studio 服务并刷新页面，以加载新脚本路由及后端保护；无需重启 TTS 引擎。已有运行中的直播会话和已经生成/下载的音频不会被追溯修改或删除，正式使用新规则前应结束旧会话并以新最终稿启动。

## 验证

```bash
python3 -m unittest discover -s tests -p test_prohibited_speech.py
python3 -m unittest discover -s tests -p test_text_studio.py
python3 -m unittest discover -s tests -p 'test_live_session*.py'
node tests/test_text_studio_risk.js
```

禁止播报单测会用 Node 对照浏览器与 Python 规则结果，验证整句移除、误报、Unicode、空文本、接口防绕过和候选过滤。`tests/text_studio_prohibited_browser_checks.js` 在隔离项目及模拟 TTS/直播接收端执行，覆盖自动标红、筛选、不能忽略、定位编辑、自动保存、重载、候选切换、导出和实际 HTTP 发送内容；禁止在真实直播管理器上运行该验收脚本。
