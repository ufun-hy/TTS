# Windows 音频生成与直播播放解耦：第二批实施记录

## 本批实现
- `/api/generation/start|pause|resume|stop` 控制音频生成。新启动采用 `autoplay=False`，生成不自动播放。
- `/api/playback/status` 和 `/api/playback/start|pause|stop` 控制当前生成 Session 对应的 Windows 播放队列。
- 新 Session 初始播放状态为 paused；用户显式点击“开始播放”后才放行缓存领取。
- 暂停、停止生成不再改变独立播放控制状态。停止播放不请求停止 TTS。
- `/api/live/*` 旧接口保留原有自动播放语义，供旧客户端和现有测试兼容。
- Web 直播页分别显示“音频生成”和“直播播放”按钮与状态。
- 增加解耦控制回归测试，更新已有前端断言。

## 本批边界（不能误认为已经做完）
1. 此版本播放仍绑定当前 Session，不能直接选取任意本地历史音频文件；下一阶段需要本地音频库存资源管理与播放列表。
2. `/api/live/reset` 仍清理原 Session 缓存。新独立模式在播放控制处于 running 时拒绝重置，但暂停或停止后仍可清理；**用户应避免在未导出或保存库存前重置**。
3. 当前 LiveSession 仍保留按播放缓冲余量回压生成的设计；“停止播放也可离线积累 6～12 小时库存”尚未实现，需要解耦产量阈值和持久化配额。
4. 当前只有一个生成 Session 与其播放 Session，尚不能跨项目独立选择多个播放任务。
5. 音频仍走旧 Audio Cache 与 Windows 播放服务，未迁移新本地库存/队列，也未修改 WinMM。
6. 桌面窗口/WebView2 及本轮新接口均没有经过 Windows 真实机器验收。

## Windows 验收
- 启动一份已泛化最终稿，点击“开始生成音频”，确认不会自动开始播报。
- 有库存后点击“开始播放”，确认恢复 WinMM 播放。
- 点击“暂停生成”时，播放已有音频继续；恢复生成不改变播放状态。
- 点击“暂停播放”时，TTS 仍可继续到既定回压阈值，不应被播放按钮直接停止。
- 点击“停止播放”时，后台生成任务不会被停止；重新点击“开始播放”可继续消费当前 Session 库存。
- 点击“停止生成”时，已经存在的库存仍可播放；停止播放后执行重置才会清理该 Session。
- 重新启动桌面 UI 后，实时状态正确恢复。
- 完成 Python 单元测试、HTTP API 验证以及 Windows 实机连续播放测试，**通过前不得宣称整体验收完成**。
