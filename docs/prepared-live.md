# 首轮准备与持续随机智播

## 泛化与首轮音频准备同时进行

文本准备页默认勾选“泛化时同步准备首轮音频”。开始普通泛化或整组泛化时会保存项目并启动后台准备；每批/每组泛化保存后更新计划，文字模型继续处理下一批，同时一个后台 TTS 线程逐块合成。也可对已有候选点击“准备首轮音频”，或随时“暂停准备”。提前准备不会向 Windows 队列发送音频，也不会自动开播。

候选只在首次进入准备计划时独立随机选择；后续批次追加不重选之前的单元。整组模式按完整组选择一个版本。遇到未完成单元/组只准备其前面的连续部分；不完整句子和仍可能吸收下一批文字的最后一块暂不合成，全文完成后才释放尾块。现有合块算法保持不变。

保存编辑、人工确认/恢复屏蔽或音色变化时，计划重新校验，仅匹配当前文本及音色指纹的音频计为已准备。未改变的块可以复用；修改长度影响后续合块边界时，这些受影响块也需重新准备。旧的在途合成结果不计入新计划进度。实时日期/时间占位符沿用提前准备报错规则。

点击开播前会先保存项目。服务端重新校验请求的全部候选、审核结果和音色，匹配后沿用同一份首轮选择与已准备 WAV，缺少的块由 Live 补齐；不会在开播时重新随机一次。首轮发送后继续按原有规则随机合成后续轮次。启动 Live 会暂停后台准备的新请求，已发出的同步 TTS 请求等待返回。

运行数据放在 `runtime/text-studio/audio-preparation/<project_id>/plan.json` 和共用的 `audio/`，与项目正文及源码分开。刷新页面会恢复进度；服务重启保留计划和音频，但不会自动启动 GPU 工作，点击继续即可恢复。一次只主动准备一个项目，切换到新项目开始准备会暂停原项目；已有文件不自动删除。

职责：`server/first_round_plan.py` 负责选择与稳定分块，`server/first_round_preparation.py` 负责后台串行合成和持久化，`web/text-studio-preparation.js` 展示状态并控制开始/暂停。相关接口为 `/api/preparation/start`、`/api/preparation/pause`、`/api/preparation/status?project_id=...`。TTS 不可用或某个组需处理时，项目保存和文字泛化仍可继续。

普通直播提交每个话术单元的所有候选和各自的人工确认记录，服务端先过滤不可播内容，再为每个单元独立随机选一个候选，按原稿顺序合块。首轮全部准备好后发送，随后继续重新选候选、合块、合成、发送。整组模式仍按组选择完整版本，保持组内上下文一致。

## 行为

- 只预生成首轮作为启动库存；后续持续使用新随机组合，不自动重播首轮，不插入兜底音频。
- 保留现有合块边界规则和顺序。各单元的候选编号独立抽取，不固定种子，也不全篇统一抽一个编号。有其他组合时避免相邻整轮完全相同，但不保证每一句每次都换版本。
- 没有未 ACK 数量上限，也不因 Windows 高水位、低水位、缺少状态或离线而停止合成/发送。旧 LIVE_BUFFER_HIGH_SECONDS/LOW_SECONDS 环境变量不再参与控制，backpressure_active 状态兼容保留为 false。
- 人工 Pause/Resume/Stop、TTS 错误和网络错误处理保留。同步合成/入队请求不能被立即取消；Windows 已下载的音频由客户端控制。
- Windows 首次 startup buffer 保留；已经开播的会话，缓存耗尽后有短音频就恢复，不再等它凑够 12 秒。历史 buffering 元数据也按这条规则恢复。
- ACK、claim lease、WAV 预处理和内容缓存协议保持原样。ACK 代表接收完成，不代表播放完成。

## 缓存和内容

首轮文件保存在 runtime/prepared-live/<session_id>/，用于发送该首轮；不会用它无限循环补缺。Gateway 对完全相同文本与声音继续命中 runtime/tts-cache/，这属于正常合成请求复用，不是兜底选旧话术。停止后文件保留，不自动清理。

普通候选过滤仍核对候选编号、文本、命中位置和人工确认；完全被屏蔽的候选不参与随机选择。运行会话固定启动时的候选池，修改候选后需新开会话。首轮如选到实时日期/时间占位符，沿用准备前报错，以免批量准备过期时间。

只要实际 TTS 产出长期低于消费速度，首轮库存最终仍可能耗尽；本方案消除人为停产和额外 rebuffer 等待，不承诺凭空补足音频。

## 状态与生效

phase=preparing 表示首轮准备；phase=playing 表示发送首轮或持续生成发送后续轮次，不代表 Windows 此刻一定在播放。prepared_segments/preparation_total_segments 显示首轮准备进度，preparation_total_rounds 固定为 1。round_number、generated_segments、total_segments 跟随当前发送轮次。

更新代码后需重启 Text Studio、刷新页面并新开会话，旧会话的单候选池不会自动扩充。Windows 恢复播放的修改需要更新客户端程序。不会创建新 Git 分支或 worktree。
