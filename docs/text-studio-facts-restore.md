# Text Studio：商品事实一致性 + 原稿还原

## 商品事实一致性

项目级配置：
- 产品到手价格
- 是否包邮
- 是否有运费险
- 是否包赔
- 发货时间口径
- 主播人设（女性 / 男性 / 中性）

Text Studio 扫描最终话术中的冲突表达，支持定位与批量修正。价格和主播称谓等确定性冲突直接统一；运费险、包赔、包邮、发货时间等整句语义在修正后按当前 Provider / Model 做必要自然化，避免简单删词形成残句。

## 原稿还原

用于主播把同一份话术稿重复朗读多轮的 ASR 文本。目标不是普通语义去重，而是：
- 按顺序相似度检测重复轮次；
- 选择完整度较高的轮次作为骨架；
- 多轮对齐补回明显漏读；
- 单轮独有内容标为疑似临场插话，不自动并入标准稿；
- 输出一份标准原稿，再进入商品事实统一与批量泛化。

前端提供“分析重复轮次 / 应用还原稿”入口；后端 `server/script_restore.py` 提供可测试的重复轮次检测和对齐核心，便于后续把分析迁移为服务端接口。

## 本轮验收：候选、导入与项目保存

- 一致性检查覆盖每个话术单元的原稿及全部候选，结果标注候选编号，支持定位。批量修正保留候选数量和选中位置；同步修正泛化输入，避免重生成再次使用旧事实。复杂表达的模型润色如果重新引入规则可识别的冲突，会回退到确定性修正文本。模型不可用时保留修正结果及句末标点。
- “接续已有项目文稿”读取 `runtime/text-studio/projects/*/project.json` 的各段当前候选，未泛化段使用 `original_text`，没有段落时使用 `source_text`；复制到新的临时项目后重新整理话术单元。来源项目保留。清洗版真实项目存在 `source_text` 为空、正文位于 `paragraphs` 的情况，不能仅导入 `source_text`。
- `recording_transcript` 完成清理后将结果持久化到 `runtime/recording-transcript/results/<job_id>.json`，正文为 `text`。录音页面提供历史结果及“在 Text Studio 继续”；Text Studio 的独立“稿清理结果”入口读取同一结果目录，以副本整理为话术单元。原清理文件不改写，来源 ID 和文件名保存到 `source_name`。这与复制其他 Text Studio 项目是两个明确区分的入口。
- 自动保存写入 `project_kind: draft`，点击“立即保存”转为 `saved`。默认列表显示正式项目；“显示临时 / 历史记录”可恢复草稿和历史项目，当前草稿单独显示为“当前临时”。历史自动保存与手动保存的数据结构相同；所有缺少 `project_kind` 标记的历史记录默认归入临时记录，不再根据名字或候选数量推测正式保存意图。打开历史项目后点击“立即保存”即可原 ID 转正。没有删除或迁移任何现存项目文件。
- `GET /api/projects` 默认隐藏临时记录，`?include_drafts=1` 返回全部记录。省略保存类型的旧 API 调用保留现有类型，新建默认正式，兼容旧客户端。

## 话术单元

`server/speech_units.py` 负责无时间戳文稿的分组，HTTP、项目保存仍在 `server/text_studio.py`。解析保留空行划分的原段，句号、问号、感叹号、分号和换行作为强边界，每个完整句子独立成单元，不再合并相邻完整句。超过 40 字的单句尝试在逗号处分组，目标约 15～35 字；连续价格、数量、规格、赠品、物流及售后条件保守保留。数字内部和引号、括号内的逗号不作为细分位置，不按固定字数硬切。每个单元保留 `source_paragraph_index`、`source_start`、`source_end`，初次解析时可定位完整原稿中的原段位置。

旧项目不会自动重切或丢弃候选；可通过“导入为新话术单元”复制当前文稿并重新泛化。泛化、搜索、风险检查、试听及智播沿用原有段落接口，现在以话术单元为工作粒度。

限制：分组是标点及事实关联规则，不是模型语义分析；没有安全停顿或连续事实组合的长句会完整保留，超过 40 字时页面提示人工检查。短完整句不为凑长度而合并。细分保留原始逗号，不自动改写为句号，确保原文及来源位置准确；模型泛化逻辑未改动。事实检查仍为规则识别，无法证明未识别表达的事实一致性。原稿区域保留输入文本，事实修正后的各单元是后续泛化依据。

## 验证

```bash
python3 -m unittest discover -s tests -p 'test_speech_units.py'
python3 -m unittest discover -s tests -p 'test_text_studio*.py'
python3 -m unittest discover -s tests -p 'test_live_session.py'
python3 -m unittest discover -s tests -p 'test_script_restore.py'
python3 -m unittest discover -s tests -p 'test_recording_transcript.py'
python3 -m unittest discover -s tests -p 'test_transcript_handoff.py'
```

上述相关测试通过，包括完成清理、落盘、服务重建后恢复，以及 Text Studio HTTP 读取的集成测试。`tests/text_studio_browser_checks.js` 可在独立临时数据目录的 Text Studio 页面中执行（例如 ego-browser `page.evaluate` 加载该文件内容）。它会创建验证项目，覆盖隐藏候选修正、句末标点、拒绝润色恢复旧事实、切换候选、保存恢复、临时列表隔离及导入不覆盖来源，勿在真实项目服务运行。

真实“石榴田间甜果-自然语言清洗版”项目的当前文稿由 44 段分为 394 单元，中位长度 26 字、最长 68 字，341 个（约 87%）在 15～35 字之间，5 个超过 40 字；忽略排版空白后的全文及顺序完全保留。验证未调用实际模型、TTS 或 Windows 播放端。

`test_script_restore.py` 已恢复 PASS。原算法最少间隔 18 句才搜索重复起点，且丢弃少于 12 句的轮次；现统一以六句探测窗口为最小完整轮次，支持两轮及三轮短稿重复，保留短文本和非重复文稿。

更新后需重新启动 Text Studio 和录音转文稿服务并刷新页面才能加载后端拆分及列表逻辑。验证使用独立 18770 / 18771 端口及临时数据目录，未重启原有服务。浏览器验收通过录音页面上传、清理结果持久化、继续链接及话术单元导入（ASR 使用测试替身，清理函数为真实实现）。本轮不修改清理算法；其既有小数点标点转换问题仍存在（例如 `9.9` 可能变为 `9。9`），接续会原样保留清理输出，使用前仍需事实检查。


### 完整句切分回归

`tests/test_speech_units.py` 覆盖强标点及换行不合并、价格数量规格保护、长逗号句、条件承接、引号及数字逗号、源位置映射、旧项目保存与打开不重切。`tests/speech_units_browser_checks.js` 在独立临时数据服务验证页面解析、保存重开及旧候选/人工编辑/商品事实保留；该脚本会创建验证项目，不应在真实数据服务运行。

本轮只修改新解析/重新解析的切分逻辑及提示，不迁移旧项目，不修改泛化 Provider 或 TTS Gateway。原运行服务需重启并刷新页面，随后主动解析或导入副本才会使用新规则。
